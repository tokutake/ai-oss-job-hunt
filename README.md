# AI OSS Job Hunt

AI を使って OSS の小さな課題を調査し、理解し、提案を作り、本人のレビューを経てコントリビュートするための作業台です。目標は採用実績を誇張することではなく、公開された成果物と判断の過程を積み上げることです。

## はじめ方

1. [案件候補の評価基準](docs/issue-selection.md)を読み、Issue を評価します。
2. 候補を [Issue / PR 台帳](TRACKER.md)に記録します。着手前に Issue と現在の PR を再確認してください。
3. Issue の内容を読み、再現方法・期待動作・受け入れ条件を自分の言葉で説明します。
4. 実装案と差分を作ったら [初期レビュー手順](docs/review-workflow.md)に沿って本人が確認します。
5. 本人の明示的な OK の後にだけ、外部リポジトリへ PR を提出します。
6. 結果と学びを [実績記録](ACHIEVEMENTS.md)に残します。

## 運用ルール

- Issue の担当者・メンテナーが作業を歓迎していることを確認し、必要なら先にコメントで確認します。
- 既存 PR、Issue の重複、最近のコミットを確認します。競合していれば別候補を選びます。
- 最初は一つの不具合、一つの目的に絞り、無関係な整形や依存更新を混ぜません。
- AI が書いた説明やコードも本人が読み、根拠・影響範囲・検証結果を説明できる状態にします。
- 外部へのコメント、ブランチ push、PR 作成はユーザーのレビュー後に行います。
- 採用活動で示す場合は、自分が担当した範囲と AI の支援を正確に説明します。
