# 人間によるレビュー手順

AI が候補 Issue を探して修正案を作り、あなたが採用担当兼最初のレビュー担当になります。

[English](review-workflow.md)

## 役割

- **AI（応募者）:** Issue とコードを調査し、選定理由を説明し、修正・検証・上流への提案文を準備します。
- **あなた（レビュー担当）:** Issue の理解、方針、差分、検証を確認し、提出可否を判断します。
- **外部提出:** あなたのレビューと明示的な承認後にだけ、AI がコメントや PR 提出を行います。

## AI のレビュー依頼に含めるもの

1. Issue URL と受け入れ条件
2. 選定理由、重複 PR とメンテナーの意向をどう確認したか
3. 原因の説明と根拠となるファイル・行
4. 変更内容、代替案、互換性、副作用
5. 実行した検証と結果。失敗や未実施も明記
6. 差分全体と、判断が必要な箇所
7. 上流へのコメントや PR の草案

## レビューチェックリスト

- AI は Issue と受け入れ条件を正しく理解しているか。
- 変更は小さく、Issue の範囲内か。
- 差分の各部分が何をし、なぜ必要かAIは説明できるか。
- 境界条件、型、アクセシビリティ、セキュリティを検討したか。
- 検証は変更に合っており、失敗・未実施を開示しているか。
- 上流の貢献ガイド、ライセンス、CLA、PR テンプレートを確認したか。
- 提案がAIによる成果だと明確に説明されているか。

## 判断

- **承認:** AI に上流への提出を明示的に依頼します。
- **修正依頼:** AI が修正し、差分全体を再度レビューします。
- **見送り:** 重複、説明不足、メンテナーの懸念、検証不能が残れば理由を記録して別候補を探します。

AI の出力を正しいと決めつけません。この実験では成果物だけでなく、AIが判断と説明に責任を持てるかも試します。
