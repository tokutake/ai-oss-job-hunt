# 人間によるレビュー手順

候補探しと初期調査は AI が主体となって進めます。人間のレビューで文脈、判断、説明責任を加えてから外部に提出します。

[English](review-workflow.md)

## 役割

- **AI:** 主体的に候補 Issue を探し、リポジトリを調査し、範囲を絞った変更を提案・検証して、判断の根拠を説明します。
- **人間のレビュアー:** Issue 選定と変更案を評価し、文脈を補い、誤りを見つけ、提出可能か判断します。
- **外部提出:** コメントや PR は、人間のレビューと明示的な承認後にだけ提出します。

## AI のレビュー依頼に含めるもの

1. Issue URL と受け入れ条件
2. 選定理由、重複 PR とメンテナーの意向をどう確認したか
3. 原因の説明と根拠となるファイル・行
4. 変更内容、代替案、互換性、副作用
5. 実行した検証と結果。失敗や未実施も明記
6. 差分全体と、人間の判断が必要な箇所
7. 上流へのコメントや PR の草案

## レビューチェックリスト

- AI は Issue と受け入れ条件を正しく理解しているか。
- 変更は小さく、Issue の範囲内か。
- 差分の各部分が何をし、なぜ必要かを AI が説明できるか。
- 境界条件、型、アクセシビリティ、セキュリティを検討したか。
- 検証は変更に合っており、失敗・未実施を開示しているか。
- 上流の貢献ガイド、ライセンス、CLA、PR テンプレートを確認したか。
- AI と人間それぞれの貢献を正確に表現しているか。

## 判断

- **承認:** AI が上流へ提出することを明示的に許可します。
- **修正依頼:** AI が修正し、差分全体を再度提示します。
- **見送り:** 重複、説明不足、メンテナーの懸念、検証不能が残れば理由を記録し、次の候補を探します。

AI が主体的に動き、人間のレビューが外部貢献の質と説明責任を高める協働を目指します。
