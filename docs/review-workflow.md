# 初期レビューの運用

## 役割

- **AI**: Issue とコードの調査、候補案、差分、影響範囲、検証手順を提示する。
- **本人**: Issue の理解、方針選択、差分の読み合わせ、動作・検証結果の確認、外部提出の最終判断を行う。
- **提出**: 本人が明示的に承認した後に行う。レビュー前に外部へコメント、push、PR 作成をしない。

## レビュー依頼に含めるもの

1. Issue URL と受け入れ条件
2. 原因についての説明と根拠となるファイル・行
3. 変更するファイルと変更内容
4. 代替案、互換性や副作用
5. 実行した検証と結果。未実行のものも明記
6. 差分全体と、本人が特に見てほしい箇所

## 本人の確認項目

- 問題と受け入れ条件を自分の言葉で言えるか。
- 変更が Issue の範囲内で、必要最小限か。
- 差分の各行について、何をし、なぜ必要か説明できるか。
- エラー処理、境界条件、型、アクセシビリティ、セキュリティへの影響を見たか。
- 検証内容が変更に合っており、失敗や未実施を正しく報告しているか。
- 上流リポジトリの CONTRIBUTING、ライセンス、CLA、PR テンプレートに従っているか。

## 判断

- **承認**: 本人が理解し、差分と検証に納得した場合。外部提出を明示的に依頼する。
- **修正依頼**: 指摘を台帳に記録し、修正後に差分全体を再レビューする。
- **見送り**: 理解できない点、重複、メンテナーの意向、検証不能が残る場合。学びを記録して別候補へ移る。

「AI が作ったから大丈夫」とは扱わず、本人が理解していない変更は提出しません。
